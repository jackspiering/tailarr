## Medium findings

### M1 — RedactRepoURL returns raw credential URL on url.Parse failure

**Location:** internal/security/names/names.go:129-131 · **Confidence:** high (runtime-reproduced)

```go
u, err := url.Parse(raw)
if err != nil {
    return raw
}
```

**Impact:** `url.Parse` fails on invalid percent-escapes (e.g. `%zz`). Reproduced: `https://alice:s3cr3t@example.com/a%zz` → returned **unchanged, credentials included**. The TUI config-edit flow (M7) and doctor display (doctor.go:90) consume this as their only redaction, so a typo'd credential URL is echoed raw. `ValidateRepoURL` (names.go:88-91) compounds it by wrapping `url.Error` with `%w`; the message embeds the full URL, so the error path leaks too.

**Fix:** On parse failure never return the input — fall back to a regex strip (`(?i)(https?|ssh)://[^\s/@]+@` → `$1//`) or over-redact. Build `ValidateRepoURL` errors without embedding the raw URL.

### M2 — Save round-trip corrupts valid `ssh://git@host/...` URLs

**Location:** internal/security/names/names.go:133-135 + internal/config/config.go:189 · **Confidence:** high (runtime-reproduced)

```go
if u.User != nil {
    u.User = nil
    return u.String()
}
```

**Impact:** `ValidateRepoURL` permits username-only ssh userinfo (`ssh://git@github.com/org/repo.git` is in names_test.go:74's valid list), but `Save` writes `RedactRepoURL(cfg.RepoURL)` which strips *all* userinfo. Reproduced: `ssh://git@github.com/org/repo.git` → `ssh://github.com/org/repo.git` on disk. Next run, git connects as `$USER` instead of `git`; clone/pull fails confusingly. Load/Save disagree on accepted URL shape.

**Fix:** For the ssh scheme drop only the password, preserve the username (or strip userinfo only for https). Add a round-trip test: every valid-list URL must survive `RedactRepoURL` unchanged when password-free, and its output must pass `ValidateRepoURL`.

### M3 — jsonSecretRE misses suffixed secret keys

**Location:** internal/security/redact/redact.go:37 · **Confidence:** high (runtime-reproduced)

```go
var jsonSecretRE = regexp.MustCompile(`(?i)("` + secretKeyPattern + `"\s*:\s*")[^"]*(")`)
```

**Impact:** `{"client_secret":"hunter2"}` and `{"access_token":"x"}` pass through `Text()` unredacted (colon form needs `\b` — `_` defeats it; line form needs `=`). `"api_key"` *is* matched, so coverage is inconsistent. Compose/log JSON output leaks these fields.

**Fix:** Wrap keyword with the suffix class `lineSecretRE` uses: `("?[A-Za-z0-9_]*?<KEY>[A-Za-z0-9_]*"?\s*:\s*")[^"]*(")`. Add `client_secret`/`access_token`/`refresh_token` to the test table (redact_test.go:101-105).

### M4 — colonSecretRE redacts only the first token of multi-word secrets

**Location:** internal/security/redact/redact.go:40 · **Confidence:** high (runtime-reproduced)

```go
var colonSecretRE = regexp.MustCompile(`(?i)(\b` + secretKeyPattern + `\b\s*:\s*)[^\s,;]+`)
```

**Impact:** `PASSWORD: correct horse battery` → `PASSWORD: [redacted] horse battery`. Violates the package's own policy (redact.go:31-33: "a partial secret is worse than losing trailing text") that `lineSecretRE` already implements.

**Fix:** Extend value class to end of line (`[^\n]+`), accepting over-redaction. Add a multi-word colon-value test.

### M5 — authkeys Load silently swallows failed chmod

**Location:** internal/authkeys/authkeys.go:45-48 · **Confidence:** high

```go
if info.Mode().Perm()&0o077 != 0 {
    _ = f.Chmod(0o600)
}
```

**Impact:** When tightening fails (root-owned 0644 from an earlier install, read-only FS), the error is discarded and Load proceeds — keys stay group/world-readable while README.md:224 promises mode-600 secrets.

**Fix:** Return the chmod error (fail closed), consistent with the codebase's posture elsewhere.

### M6 — !unix builds: check-then-act nofollow, undocumented weaker guarantee

**Location:** internal/security/paths/nofollow_other.go:11-23 · **Confidence:** high

```go
if IsSymlink(path) {
    return nil, fmt.Errorf("refusing to open symlink: %s", path)
}
return os.OpenFile(path, flag, perm)
```

**Impact:** Unix builds are atomic via `O_NOFOLLOW` (nofollow_unix.go:14). On `!unix`, a symlink swapped between check and open/chmod redirects the operation to an arbitrary target — affecting atomic/write.go:62's post-rename chmod and logging/log.go:49's open. README.md:222-223 promises symlink refusal with no platform caveat.

**Fix:** Document the weaker guarantee per platform (package doc + README); ideally implement a Windows atomic equivalent or refuse when no atomic primitive exists.

### M7 — Unvalidated RepoURL flows into raw-rendered status/error paths

**Location:** internal/ui/app.go:661 (assign), 641 (`m.cfg.String()`), 676-680 (Save error echo) · **Confidence:** high

```go
if cfg.RepoURL, err = ui.Line("TAILARR_REPO_URL", cfg.RepoURL); err != nil {
```

**Impact:** Config-edit assigns raw input with no validation; `Save` validates later, but before that both the "view" status and the Save error string (which embeds the raw URL per M1) render verbatim — the one TUI surface not passing through `redact.Text` (compare app.go:882). Combined with M1, a typo'd credential URL reaches the terminal. Self-entered, display-only, not persisted — hence Medium.

**Fix:** Validate immediately after `ui.Line` returns; wrap status-panel error strings with `redact.Text` at the render site.

### M8 — `export FOO=bar` parses as key `export FOO`

**Location:** internal/scaletail/env.go:43-53 (and ReadEnvKeys ~132) · **Confidence:** high

```go
key, value, ok := strings.Cut(line, "=")
```

**Impact:** Shell-style env lines yield key `export TS_AUTHKEY` — the intended variable is silently never set, merge never sees it, and `WriteEnvFile` can write the bogus key back. A single upstream `export` line silently disables service auth.

**Fix:** Strip one leading `export ` (+ whitespace) after BOM/trim in both `ParseEnvFile` and `ReadEnvKeys`. Add a test.

### M9 — Git timeout kill strands `.git` locks with no recovery path

**Location:** internal/scaletail/repo.go:33-41 (kill), :28 (5-min timeout) · **Confidence:** medium (kill semantics verified; lock-stranding inferred from git behavior — needs runtime confirmation)

```go
cmd := exec.CommandContext(ctx, "git", gitHardened(args...)...)
```

**Impact:** `CommandContext` kills only the direct `git` child; `git-remote-https`/ssh helpers survive. A kill mid-write leaves `.git/index.lock`/shallow locks; every later `Refresh` fails with "Unable to create index.lock" and nothing in the codebase recovers. One network stall can wedge the tool until an operator manually deletes lock files.

**Fix:** Set `cmd.WaitDelay` / process-group kill so helpers die with the parent; on timeout, remove stale `.git/*.lock` when no git process is alive and append remediation text to the error.

### M10 — SIGINT/SIGTERM dropped while the terminal is released

**Location:** internal/ui/app.go:31-42 (leaveTUI), 136-145 (contradicting comment); bubbletea v1.3.10 options.go:91, tea.go:298 (verified in module cache) · **Confidence:** medium (mechanism verified; window timing-dependent)

```go
// app.go:141-144 — describes a path that cannot occur:
// Routine user cancellation mid-prompt (Ctrl-C while the terminal is
// released for a stdin prompt) is a clean exit, not an error.
```

**Impact:** Every interactive op runs under `leaveTUI()` → `prog.ReleaseTerminal()`, which sets bubbletea `ignoreSignals=1`; its handler drops SIGINT/SIGTERM while the default kill disposition stays suppressed. Ctrl+C during a prompt or the up-to-5-minute git refresh (repo.go:28) does nothing; `kill`/`systemctl stop` is ignored mid-prompt. Only the docker-exec window is cancellable (compose.go:120 `signal.NotifyContext`).

**Fix:** Install a temporary signal handler during released-terminal windows that cancels the running prompt/refresh; update the app.go comment to match.
